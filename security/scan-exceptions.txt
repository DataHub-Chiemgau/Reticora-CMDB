# Accepted findings of the dependency and container scans (SEC-11, WP-004,
# WP-389).
#
# One finding per line:
#   "<ID> exp:<YYYY-MM-DD> since:<YYYY-MM-DD> sev:<critical|high> # <reason, ticket>".
# IDs: Go vulnerability IDs (GO-YYYY-NNNN) for govulncheck, GHSA IDs for
# npm audit, CVE IDs for Trivy. The format is the .trivyignore format, so the
# file is passed to Trivy unchanged (Trivy skips since: and sev:).
#
# since: is the day the finding was first reported, sev: its severity. Every
# entry needs an expiry within the CVE fix SLA of SEC-11, counted from
# since: Critical at most 7 days, High at most 30 days. Expired entries no
# longer suppress the finding, so the scan fails again.
# scripts/ci/check-scan-exceptions.sh enforces this before every scan (an
# entry without exp: would suppress its finding in Trivy forever). See
# docs/security/abhaengigkeitsscans.md.
